# Contributing to AirWatch Pro

First off, thank you for considering contributing to AirWatch Pro! It's people like you who make it a great tool for industrial AQI monitoring.

## Code of Conduct

By participating in this project, you are expected to uphold our Code of Conduct:
- Be respectful and inclusive.
- Use professional language.
- Respect different viewpoints and experiences.

## How Can I Contribute?

### Reporting Bugs
- Use the GitHub Issue Tracker.
- Provide a clear, descriptive title.
- Describe the steps to reproduce the issue.
- Include information about your environment (OS, Python version, Node version).

### Suggesting Enhancements
- Open an issue with the tag "enhancement".
- Explain the feature and why it would be useful.

### Pull Requests
1. Fork the repository.
2. Create a new branch for your feature or bugfix: `git checkout -b feature/your-feature-name`.
3. Make your changes.
4. Ensure your code follows the project's style guidelines.
5. Run tests to ensure nothing is broken.
6. Commit your changes with a descriptive message.
7. Push to your fork: `git push origin feature/your-feature-name`.
8. Open a Pull Request against the `main` branch.

## Development Setup

Please refer to the [README.md](README.md) for detailed setup instructions.

## Coding Standards

### Python (Backend)
- Follow PEP 8 guidelines.
- Use type hints wherever possible.
- Write docstrings for all public functions and classes.
- Use `pytest` for unit and integration tests.

### JavaScript (Frontend)
- Use functional components and React hooks.
- Follow ESLint and Prettier configurations.
- Use Tailwind CSS for styling.
- Ensure components are responsive and accessible.

## Git Workflow

- Keep commits small and focused.
- Use meaningful commit messages.
- Rebase your branch with `main` before submitting a PR to avoid merge conflicts.

## Testing

Always run tests before submitting a PR:
- Backend: `pytest`
- Frontend: `npm test`

Thank you for your contributions!
